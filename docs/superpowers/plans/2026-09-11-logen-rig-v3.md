# Logen Rig V3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and activate a ten-part production Logen V3 side-profile cutout rig derived from the approved master reference.

**Architecture:** Keep the existing generic `Rig2D`, `RigAnimation`, `RigAnimator`, renderer, calibration, and foot-plant boundaries. Store V3 data in its own asset directory, load V3 from `GuffmanBasementScene`, and validate the exact asset contract through C++ self-tests, focused unit tests, and a shell acceptance script.

**Tech Stack:** C++20, CMake, SDL3, SDL3_image, nearest-neighbor SDL textures, Swift/SwiftUI launcher, generated transparent PNG assets, Apple Silicon.

**Spec:** `docs/superpowers/specs/2026-09-11-logen-rig-v3-design.md`

## Global Constraints

- Use `Logen_Master_Right_v1.png` as the only visual authority for V3.
- Do not modify or delete the master, V2 PNGs, or the existing basement artwork.
- Create exactly ten V3 PNG assets with transparent backgrounds and no extra V3 PNG files.
- Keep every V3 part in strict right-facing side profile with consistent scale, palette, lighting, and pixel density.
- Keep the right sleeve empty; do not add a right forearm, hand, or hidden right-arm node.
- Preserve the current 960×540 canvas, 188 logical-pixel target height, click-to-move primary control, A/D and arrow fallback, F3/F4/F5 calibration tools, and foot-plant separation from `PlayerController`.
- Do not add gameplay systems or begin a later stage.
- Production behavior changes require a failing focused test before implementation.
